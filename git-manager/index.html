Interface web intuitive pour la gestion de vos dépôts Git locaux.

Interface git-manager

Installation

Au préalable

Git doit être installé sur le serveur avant d'utiliser Git Manager. Vérifiez avec git --version dans un terminal. Sur Windows, Git Manager est compatible avec Git for Windows.

  1. Extrayez l'archive et copiez le dossier git-manager/ à la racine de votre projet. Si le dossier extrait porte un numéro de version (ex : git-manager-1.0.1/), renommez-le en git-manager/.
  2. Créer sur votre serveur local un virtual host Apache pour le nouveau dépôt.
  3. Renommez git-config.example.php en git-config.phpet renseignez vos informations dans git-config.php :
  4. Token dans l'URL (https://TOKEN@github.com/user/repo.git) : fonctionne sans git-config.phpcar l'authentification est dans l'URL du remote elle-même.
  5. Credential Manager (git config --global credential.helper store ou wincred) : fonctionne sans git-config.phpcar les identifiants sont stockés au niveau global de Git.
  6. Le git-config.phpest vraiment indispensable pour le SSH (qui ne fonctionnera pas si sshKeyPathest vide, le processus PHP ne trouvera pas les clés).

Tant que git-config.php n'est pas configuré, un bandeau orange s'affiche en haut de l'interface git-manager pour vous le rappeler.

Voir aussi la page authentification Token/SSH dans l'interface git-manager.

<?php
return [
    // Identité Git pour les commits
    'userName' => 'votre-username',
    'userEmail' => 'votre-email@example.com',

    // Clé SSH pour l'authentification GitHub (facultatif)
    // Clé RSA : C:/Users/votre-nom/.ssh/id_rsa
    // Clé ED25519 : C:/Users/votre-nom/.ssh/id_ed25519
    'sshKeyPath' => 'C:/Users/votre-nom/.ssh/id_rsa',

    // Multi-dépôts (facultatif) — dossier contenant vos projets Git
    // Affiche un sélecteur de dépôt dans le header. Laisser vide pour désactiver.
    'reposRoot' => 'C:/Users/votre-nom/projets',

    // Options d'affichage (facultatif)
    'options' => [
        'maxHistoryItems' => 20,      // Nombre de commits dans l'historique
        'maxFileLogItems' => 10,      // Nombre de commits par fichier
    ]
];

Note : git-config.php contient vos données personnelles et ne doit pas être versionné. Il est automatiquement ajouté au .gitignore.

Lancez l'interface Git Manager

Lancez l'interface (bouton en haut ou en bas de page) — Rappel : Le dossier git-manager/ doit être copié dans le répertoire du projet :

  • Lancez git init depuis l'interface git-manager
  • Le .gitignore est automatiquement créé avec git-manager/
  • — Rappel si présence bandeau renommez git-config.example.php en git-config.php et renseignez vos informations

Cloner un dépôt existant — depuis un projet où git-manager est déjà en place, utilisez git-clone.html pour cloner un dépôt distant dans un nouveau dossier voisin. Git Manager copie automatiquement ses fichiers dans le nouveau projet.

Mode multi-dépôts

Distinction mode embedded (embarqué) vs standalone (autonome).

Par défaut, git-manager est installé dans chaque projet (embarqué) (mon-projet/git-manager/). Pour gérer plusieurs dépôts depuis une seule interface, utilisez le mode autonome.

Exemple d'installation autonome

Placez git-manager dans un dossier dédié avec son propre virtual host, en dehors de vos projets :

C:/repos/ <- reposRoot = C:/repos/ ├── gm-host/ <- Virtual host dédié (ex : git-manager.local) │ └── git-manager/ <- L'application git-manager (point d'entrée pas de .git/ → ignoré) ├── project-a/ <- Affiché dans le sélecteur │ └── .git/ <- Dépôt Git → Créé lors du git init ├── project-b/ <- Affiché dans le sélecteur │ └── .git/ <- Dépôt Git → Créé lors du git init └── project-c/ <- Affiché dans le sélecteur └── .git/ <- Dépôt Git → Créé lors du git init

Dans git-config.php, configurez reposRoot avec le chemin du dossier parent :

'reposRoot' => 'C:/sites/projets',

Comment ça fonctionne

  • Sélectionner un dépôt bascule toute l'interface sur ce dépôt (statut, branches, historique…)
  • Les autres projets n'ont pas besoin d'un dossier git-manager/
  • Un seul virtual host suffit pour gérer tous vos dépôts git
  • Sélecteur : menu déroulant affiché dans le header à côté du nom du dépôt courant — masqué si reposRoot est vide ou absent
  • Scan : liste uniquement les sous-dossiers directs de reposRoot qui contiennent un .git/
  • Sécurité : chaque chemin est validé avec realpath() pour éviter toute traversée de répertoire

Le mode multi-dépôts gère uniquement les opérations git. Pour accéder à l'application web d'un autre projet dans le navigateur, son propre virtual host reste nécessaire.

Seuls les sous-dossiers directs contenant un .git/ sont listés. Si vous déplacez votre dossier de projets, pensez à mettre à jour le chemin reposRoot dans git-config.php.

Cas d'utilisation

Nouveau projet

Initialisez un nouveau dépôt ou clonez une source existante.

Branches

Créez, basculez et fusionnez vos branches. Gérez les rebases avec les boutons Continuer / Abandonner.

Historique & Récupération

Parcourez vos commits, consultez l'historique par fichier et restaurez une version précise.

Tags & Releases

Créez des tags annotés et publiez des releases directement sur GitHub.

Stash

Mettez de côté vos modifications en cours sans commiter et reprenez-les quand vous voulez.

Synchronisation

Push, pull et fetch pour synchroniser avec GitHub ou GitLab.
